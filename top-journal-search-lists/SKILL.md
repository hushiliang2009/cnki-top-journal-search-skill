# Top Journal Search Lists

## 核心原则

ai4scholar 是中英文文献检索的主要来源。CNKI 仅作为中文论文的补充来源。所有期刊判级均以 `references/Academic_Journal_Master_Directory_20260715.md` 为准，目录版本为 2026-07-15。

CNKI 有两种彼此独立的检索模式，边界不同，不得混用。

### 模式一：公开匿名检索（默认）

只使用公开首页、固定主题检索和第一页结果。单次 `limit` 为 1 至 20。程序不登录、不下载、不持久化 Cookie，不持久化缓存，运行期仅24小时内存缓存；不使用用户浏览器配置文件，也不访问结果的详情页面。

### 模式二：WebVPN 人工值守检索（可选，须显式启用）

由使用者本人以校园账号、经所在机构官方 WebVPN 完成统一身份认证后，使用知网专业检索按期刊清单定向检索中文期刊论文。

这属于**机构授权**的正常访问路径，与检测规避有本质区别。底线不随模式改变：**不伪造** User-Agent、**不轮换代理**、不抹除自动化标志、**不自动破解**验证码。

启用时只设置 `CNKI_WEBVPN_HOME`，其值为所在机构 WebVPN 改写后的知网首页地址。`CNKI_WEBVPN_PROFILE` 不再需要。运行时使用非持久化浏览器上下文，不保存 Cookie、登录票据或浏览器 profile；服务重启后需要重新登录。

该模式**必须人工值守，不可用于定时任务**或任何无人参与的场景。三处人工介入无法自动化：

1. 统一身份认证需要校园账号密码，程序不接触凭据；
2. WebVPN 票据是 session cookie，导出后在新浏览器进程会被服务端拒绝，因此登录与检索必须同进程、浏览器窗口全程打开；
3. 中途触发安全验证时需要人工滑动。

请求携带使用者的实名机构身份，所在机构的使用规范与频率限制均适用。默认请求间隔 30 秒。

⚠ **`LY=` 并非严格精确匹配**。2026-07-30 实测（环境版同一套页面契约）：表达式
只枚举了 6 本刊，结果中仍出现来源为 `Journal of Resources and Ecology` 的记录——
该刊中文名包含清单中的「生态学报」。因此**返回的期刊不保证全部落在分组清单内**。
这类记录不会被误标：判级层如实给出空层级与 `manual_review_required=true`，
但会占用 `limit` 名额。调用方应以判级结果而非「出现在结果里」判断归属。

## 执行方法

1. 明确主题、年份、语言和数量。未指定时，以近五年为重点，并保留必要的经典研究。
2. 在 Skill 根目录校验目录：

```text
python scripts/catalog_lookup.py validate
```

3. 以 ai4scholar 为主要来源，调用 Google Scholar 和 Semantic Scholar；医学、健康和生命科学主题补充 PubMed。对关键论文可根据需要扩展参考文献、被引文献和相似论文。
4. 用户需要中文论文、近期中文研究或明确要求 CNKI 补充时，调用 `cnki_search(query, limit)`。它从 CNKI 公开首页按主题检索，仅读取第一页，最多返回 20 条期刊记录。若返回 `challenge_detected`，改用 ai4scholar，并在检索说明中写明 CNKI 补充检索未能执行。
5. 用户已启用 WebVPN 人工值守模式，且需要按中文顶尖期刊或 CSSCI 定向查证时，才使用专业检索。启用前必须告知：需要本人登录、浏览器窗口全程打开、中途可能需要人工完成安全验证。返回值中的 `human_intervention_required` 与 `complete` 必须如实转述，`complete` 为假时不得把结果当作该主题的完整中文文献。
6. 正式结果必须具有篇名、期刊和发表年度；信息不完整的记录只说明缺失项，不作为正式候选。每条记录保留 `sources`，标明 ai4scholar 或 CNKI。
7. 使用目录脚本核验期刊并按十级顺序排列：

```text
python scripts/catalog_lookup.py lookup "Journal A" "Journal B"
```

8. 同一论文优先按 DOI 去重；没有 DOI 时按规范化篇名、作者和年度去重。保留较完整的元数据和全部 `sources`。

## 期刊排序与目录例外

结果按十级期刊层级排序；第二级内部按 `ncs_internal_rank` 升序排列。第七级没有独立记录时，应明确标记为空层级，不得伪造期刊，也不得从其他层级补入记录。用户明确提供其他目录文件时，才在目录命令中使用 `--catalog` 指定该文件。

## CNKI 公开检索边界（模式一）

- 入口固定为 `https://www.cnki.net/`，字段固定为主题检索。
- 只读取第一页，结果最多 20 条。
- 出现验证码、登录页、401、403、429 或页面结构变化时立即停止，保留已获得的公开信息并报告原因。
- 不使用替代入口、代理、内部接口或浏览器历史状态。
- 用户如需全文，应根据篇名、期刊和发表年度自行前往合法渠道下载；本 Skill 不提供下载功能。

## CNKI 专业检索边界（模式二）

- 仅覆盖**中文层级**：第六级中文顶尖期刊（13 本）与第九级 CSSCI。传入 SSCI、SCIE、FT50 等英文层级会直接报错——那些层级本应走 ai4scholar。
- 第六级用 `LY=` 枚举 13 本刊；第九级在学术期刊专业检索条件区勾选来源类别 CSSCI，一次请求覆盖全部，且含扩展版，范围大于目录里去重后的 661 本。
- 分组检索依次执行 **TI → SU → KY → TKA**，并累计此前字段尚未取得的合格唯一记录；达到请求数量即停。不是"选一个最好的字段"，四个字段的结果互相补充而非互相替换。
- 页面操作顺序固定为：从知网首页进入高级检索，切换专业检索，先选择学术期刊，再确认专业检索标签，随后设置出版年度和来源类别，最后填写表达式并提交。选择学术期刊是文献类型限定，不改变原有分组或期刊范围。
- **来源类别不是专业检索字段**。CSSCI（`P0209`）和北大核心（`P01`）在选择学术期刊后显示于上方条件区，必须在提交前勾选；不写入专业检索表达式或 `LY=` 子句。控件缺失、重复或未勾选时返回 `page_contract_changed`，绝不提交未筛选检索。
- `first_page_only=true` 表示每条表达式只读取当前页最多 50 条；`complete=false` 时不得声称检索完整。
- `LY=` 可能近似命中清单外的期刊。组外记录不占限额，列入 `excluded_out_of_scope_records` 与 `excluded_out_of_scope_count`。
- `source_category_applied` 是全部已执行批次与字段的**合取**：任一批次未证实来源类别已在提交前生效，整组即报 `false`。它可能低于逐条记录的实际筛选状态，误差方向是保守低报，且必然伴随 `terminal_status` 或 `human_intervention_required=true` 供定位。
- 只检索**中文学术期刊论文**。文献类型限定由三层保证：检索范围设为学术期刊、表达式不使用跨库字段、解析层丢弃非期刊行。
- 专业检索可用字段固定为：`SU` 主题、`TKA` 篇关摘、`TI` 篇名、`KY` 关键词、`AB` 摘要、`CO` 小标题、`FT` 全文、`AU` 作者、`FI` 第一作者、`RP` 通讯作者、`AF` 作者单位、`LY` 期刊名称、`RF` 参考文献、`FU` 基金、`CLC` 中图分类号、`SN` ISSN、`CN` CN、`DOI` DOI、`QKLM` 栏目信息、`FAF` 第一单位、`CF` 被引频次。
- 表达式遵循知网页面规则：主题字段用 `%=` 相关匹配，期刊用 `LY=` 精确匹配，逻辑运算符 `AND`/`OR`/`NOT` 前后留空格。`YE` 不是可检索字段；年份只能填写在页面的出版年度起止控件中。
- `LY=` 是精确匹配且写错刊名会**静默返回空结果**，因此刊名一律取自综合期刊目录并自动展开括号全半角变体，不手工书写。
- 表达式长度受服务端限制（实测 3633 字符可用、4393 字符被拒），超限时返回「暂无数据，请稍后重试」而非报错，极易被误读成"这些期刊上没有该主题文献"。分批上限取 3000。
- `no_data_retry_later` 表示页面暂时无法给出数据，不等于空结果，不得据此得出没有相关文献的结论。
- 高级检索页**不可深链**，必须从知网首页点「高级检索」进入；深链会被判定为异常访问。
- 表达式填入后校验输入框实际接受的长度，被截断即中止——半截语法仍是合法提交，返回的却是完全不同的检索范围。
- 出现安全验证时暂停并提示人工处理，已完成批次记入断点不重跑；使用者放弃时如实报告未完成批次，不把不完整结果说成完整。

## CNKI 能力定位与已知限制

CNKI 检索是**尽力而为的补充能力**，不是可依赖的主检索路径。

知网对自动化访问有站点级安全策略。在模式一的边界内（不登录、不使用用户浏览器配置文件、不改 User-Agent、不用代理、不做任何检测规避）**可能长期返回 `challenge_detected` 而始终无法取得结果**。这属于站点侧正常防护，不是安装故障，重装、重试或更换网络都不会改变。

因此：

- `challenge_detected` 不等于"该主题无中文文献"。此时改用 ai4scholar，并在检索说明中如实写明"CNKI 补充检索未能执行，中文近期文献可能覆盖不足"。
- 不得为绕过该策略而伪造 User-Agent、轮换代理或抹除自动化标志——这些属于检测规避，两种模式都禁止。

模式二不是对上述策略的绕过，而是换用机构授权的访问路径：由使用者本人完成认证与安全验证，站点始终知道请求来自谁。它使用非持久化浏览器上下文，不读取、不复用使用者日常浏览器的会话与历史；同时不降低任何检测规避禁令，只是把"由人完成登录与验证"这件事显式化。

模式二同样有其限制：请求间隔 30 秒，连续请求仍可能触发安全验证；此时暂停等待人工处理，不重试、不切换代理。

## 输出契约

按以下顺序报告：

1. 检索范围，包括主题、关键词、年份、语言、日期和 `sources`。
2. 分层论文目录。每篇正式记录包含篇名、期刊、发表年度、期刊层级和 `sources`。
3. 文献综合，仅概括可由题录、摘要或工具返回内容核实的信息。
4. 检索说明，包括检索式、去重口径、空层级、未覆盖范围和元数据缺失。

不依据题名推测研究结论，不补造 DOI、作者、期刊、年度、引用次数或链接。未匹配期刊标记为未匹配，不自行指定层级。
