# CNKI 公开主题检索与期刊级别标注设计

设计日期：2026-07-22
状态：已批准
适用范围：`cnki-research`、`top-journal-search-lists`、MCP、Skill、插件与跨客户端安装包

## 一、最终决定

CNKI 只作为 `ai4scholar` 对中文论文覆盖及时性不足时的补充检索来源。系统从 [中国知网公开首页](https://www.cnki.net/) 执行固定的主题检索，返回公开结果页中的期刊论文清单，并依据 `Academic_Journal_Master_Directory_20260715.md` 标注期刊级别。

项目不再要求高级检索、专业检索、WebVPN、机构权限、登录、详情读取、题录导出或论文下载。用户根据返回清单自行检索和下载全文。

本设计取代此前所有 CNKI WebVPN、新版高级检索、专业检索、详情和下载设计及实施计划。旧文档只保留为历史记录，不再作为实现依据。发生冲突时，以本设计为准。

## 二、验证与压缩包复核结论

### 1. 公开入口实测

在 `https://www.cnki.net/` 首页使用默认主题字段提交“数字化转型、企业创新与新质生产力”后，能够进入 `kns8s/defaultresult` 结果页。页面显示命中总数、文献类型分布和结果表，结果表能够提供题名、作者、来源、日期、数据库类型、被引次数、下载次数及网络首发标记。

实测过程没有执行 CNKI 登录、WebVPN 跳转、详情读取或下载。实现验收还必须在全新临时浏览器上下文、空 Cookie、无 WebVPN 条件下重复该检索，以排除既有浏览器状态影响。

### 2. `cnki-search-skill-main.zip`

该包通过 `/kns8s/brief/grid` 等内部 HTTP 接口检索，检索前要求 Cookie，并默认调用 CNKI IP 登录接口。普通检索仍依赖高级检索后端，且详情、导出、下载与工作区状态存在耦合。该仓库没有开源许可证，不能复制源码或静态数据。

本项目只参考其公开结果字段和结构化错误分类，采用清洁重写，不使用其登录、Cookie、内部接口、详情、导出、下载、安装器或学科代码。

### 3. `scansci-pdf-master.zip`

该包不含 CNKI 实现。可参考的内容限于题录字段规范化、去重、分域限流、停止条件和结构化状态。浏览器缓存、`Local State`、Cookie、localStorage、SSO、WebVPN、代理轮换、Tor、验证码处理、反检测和 PDF 下载模块全部排除。

### 4. `top-journal-search-lists_Skill.zip`

该包原有 CNKI 模块以登录、WebVPN、高级检索、专业检索、详情和下载为中心，不能继续作为当前实现。保留并扩充综合期刊目录校验与期刊名称匹配能力，CNKI 部分改为公开主题检索适配器。

## 三、目标与非目标

### 1. 目标

- 从 CNKI 公开首页执行单一主题检索；
- 默认只读取第一页，最多返回 20 条期刊论文；
- 至少提供篇名、期刊和发表年度；
- 保留作者、发表日期、原始序号、被引次数、下载次数和网络首发标记等公开字段；
- 依据主期刊目录标注最高优先级、类别、来源目录和学科分类；
- 与 `ai4scholar` 结果规范化、去重并保留来源；
- 串行、低频运行，遇到验证、限流、登录跳转或页面变化立即停止；
- Codex、Claude Code、Claude Desktop 及插件使用同一实现。

### 2. 非目标

- 不使用高级检索或专业检索入口；
- 不使用 WebVPN、CARSI、SSO、机构代理或 IP 登录；
- 不读取或写入 Cookie、浏览器用户目录、缓存、`Local State` 或 localStorage；
- 不调用 `/kns8s/brief/grid`、`/senquery` 等内部接口；
- 不访问详情页，不采集摘要、关键词、机构或 DOI；
- 不生成 BibTeX、RIS、CSV 等 CNKI 专用导出；
- 不解析或保存 PDF、CAJ、详情和下载链接；
- 不自动下载全文，不接受下载目录或访问授权参数；
- 不处理或绕过验证码，不轮换代理或出口地址。

## 四、方案选择

### 1. 采用方案：检索后逐条标注

公开结果解析完成后，立即按期刊名称查询主目录，为每条期刊论文附加目录判定字段，再按目录优先级排序。未匹配记录保留并排在已匹配记录之后。

该方案一次返回完整备选清单，既能识别高等级期刊，也不会丢弃未收录的新刊或相关研究。

### 2. 未采用方案：分两步判级

先返回 CNKI 原始清单，再单独调用目录工具批量判级。该方案组件边界清楚，但用户需要额外执行一步，容易出现题录与判级结果错位。

### 3. 未采用方案：只返回目录内论文

检索后删除所有未匹配期刊。该方案清单较短，但会把目录未收录、刊名存在附加文字或暂时匹配失败的论文误作低质量结果删除。

## 五、公开检索合同

### 1. 工具接口

对外只保留一个检索工具：

```text
cnki_search(query: string, limit: integer = 20)
```

约束如下：

- `query` 是普通主题词，不接受字段表达式或专业检索语法；
- `limit` 取值为 1 至 20；
- 固定使用首页默认主题字段；
- 固定读取第一页；
- 不暴露模式、页码、登录、Cookie、WebVPN、详情、导出和下载参数。

### 2. 页面流程

1. 创建不复用用户浏览器配置的临时浏览器上下文；
2. 打开 `https://www.cnki.net/`；
3. 确认页面存在主题字段与公开检索框；
4. 填入主题词并在检索框内按 Enter 提交；
5. 等待 `kns8s/defaultresult` 结果页和结果表稳定；
6. 识别页面状态并解析第一页；
7. 只把文献类型为期刊的记录纳入备选清单；
8. 对期刊名称执行目录匹配、等级标注和排序；
9. 返回结构化结果并关闭临时上下文。

实现不得直接构造带动态令牌的结果、详情或下载 URL。公开结果 URL 只用于本次浏览器导航，不写入题录；用户可根据篇名在知网自行检索。

**关于步骤 3 不校验检索按钮**：提交动作是在检索框内按 Enter，不点击按钮，因此按钮不是流程正确性的必要条件。而知网对自动化访问的拦截（见第八之二节）使我们无法取得真实结果页来确认按钮的选择器；一个猜测的选择器会把本可正常工作的路径变成永久失败，其代价高于它能带来的契约保障。首页契约由「主题字段 + 检索框」两项校验，二者的选择器已在真实页面上验证通过。

步骤 5 的等待选择器与结果解析器使用同一个类名：若知网改名，解析本就会失效，此处不引入新的失败面，只是把静默失败变成响亮失败。

## 六、题录与目录判定结构

### 1. 基础题录字段

每条备选记录至少返回：

| 字段 | 含义 |
|---|---|
| `title` | 篇名 |
| `authors` | 作者列表；页面无法可靠解析时为空列表 |
| `journal_raw` | CNKI 结果页显示的原始期刊名称 |
| `publication_date` | CNKI 页面原始发表日期 |
| `publication_year` | 从有效日期提取的四位年份，无法确定时为 `null` |
| `document_type` | 固定为已确认的期刊文献类型 |
| `citations` | 公开结果页被引次数，缺失时为 `null` |
| `downloads` | 公开结果页下载次数，缺失时为 `null` |
| `is_online_first` | 是否具有网络首发标记 |
| `result_rank` | CNKI 原始结果序号 |
| `source_database` | 固定为 `CNKI` |
| `search_query` | 本次主题检索词 |

篇名、期刊和发表年度是必需字段。任一字段缺失时，该记录不进入正式备选清单，而是保留在 `incomplete_records` 中供人工复核；工具状态设为 `partial`，不得按当前年份推断发表年度。

### 2. 目录判定字段

每条记录附加：

| 字段 | 含义 |
|---|---|
| `journal_matched_title` | 主目录中的规范期刊名称 |
| `journal_match_status` | `matched`、`unmatched` 或 `ambiguous` |
| `journal_match_method` | 成功时为 `normalized_exact` 或受控别名方法 |
| `priority_level` | 主目录第 1 至第 10 级，未匹配时为 `null` |
| `priority_group` | 目录分组标识 |
| `source_catalogs` | 该期刊命中的全部来源目录 |
| `subject_categories` | 来源目录中的学科分类列表 |
| `ncs_internal_rank` | 第二级内部顺序，其他层级为 `null` |
| `catalog_version` | 固定为 `2026-07-15` |
| `manual_review_required` | 未匹配或歧义时为 `true`；不完整记录固定为 `true` |

十个优先层级依次为：经济学 Top 5、NCS/PNAS、UTD24、FT50、Field Top、中文顶尖期刊、其他顶尖期刊、SSCI、CSSCI、SCIE。

### 3. 匹配规则

- 始终保留 `journal_raw`，不得用规范名称覆盖原始来源；
- 使用 Unicode NFKC、大小写折叠、空格和常见标点规范化；
- 兼容全角半角括号及间隔号差异；
- 允许受控清除“网络首发”等明确的展示附加文字；
- 常用别名只能来自版本化、可测试的别名表；
- 不使用无约束模糊匹配，不根据题名、作者或 CNKI 页面标签推断期刊级别；
- 同一期刊的**书写变体**归并为一个条目，取数值最小的最高优先级，并保留全部来源目录与学科分类。
  书写变体限于以下四类，不得扩大：① 冠词 `The` 有无；② `&` 与 `and`；③ 副标题分隔符 `:`、`-`、`,`；
  ④ 全角半角括号与大小写差异；
- 归并后规范化键**仍存在多个不同期刊候选**时标记 `ambiguous`，不得自动选取。
  句点等未列入书写变体的差异（如 `A.B` 与 `AB`）属真歧义，必须保留 `ambiguous`；
- 同一期刊命中多个目录时采用数值最小的最高优先级，同时保留全部来源目录与学科分类；
- CNKI 显示的核心、CSSCI 扩展等标签只可作为原始页面信息，不参与等级判定。

### 4. 排序规则

1. 已匹配记录排在未匹配和歧义记录之前；
2. 已匹配记录按 `priority_level` 从 1 到 10 排序；
3. 第二级内部按 `ncs_internal_rank` 排序；
4. 同级记录保持 CNKI 原始 `result_rank`；
5. `unmatched` 和 `ambiguous` 保持 CNKI 原始顺序。

## 七、与 ai4scholar 的关系

`ai4scholar` 仍是主要文献检索来源。CNKI 公开检索仅在用户需要中文论文、近期中文成果或补充检索时调用。

合并时依次使用：

1. DOI 精确匹配，但 CNKI 公开结果通常不提供 DOI；
2. 规范化篇名、第一作者和发表年度；
3. 只有篇名高度一致但其他字段不足时标为候选重复，不自动删除。

合并后的记录保留 `sources` 和各来源原始字段。期刊级别统一由主目录判定，不采用 ai4scholar 或 CNKI 自带的期刊标签覆盖目录结果。

## 八、限流、状态与停止规则

### 1. 运行约束

- 同一时刻只允许一个 CNKI 页面操作；
- 默认一次主题检索、一次结果页解析，不自动翻页；
- 同一规范化查询在短期缓存命中时返回公开题录缓存，建议 TTL 为 24 小时；
- 缓存只保存查询、公开题录、目录判定、状态和时间，不保存 URL 令牌或浏览器状态；
- 不并发执行多个 CNKI 查询，不在失败后切换入口。

### 2. 状态

工具返回下列状态之一：

- `success`：成功返回完整备选清单；
- `no_results`：结果页明确显示无结果；
- `partial`：部分记录可用，但存在字段缺失或解析中断；
- `rate_limited`：出现 429 或访问频繁提示；
- `challenge_detected`：出现验证码或交互验证；
- `login_required`：跳转至登录、SSO 或机构认证页面；
- `forbidden`：出现 401、403 或拒绝访问；
- `page_contract_changed`：关键控件、结果结构或本地综合期刊目录契约不能可靠识别。
  目录缺失属部署配置错误，必须在发起任何 CNKI 请求之前拦下，不得重试，也不得报成 `network_error`；
- `network_error`：公开页面网络访问失败。

除普通网络错误或 5xx 可在等待后重试一次外，其他异常均立即停止。不得要求用户登录或处理验证码，不得切换代理、WebVPN、内部接口或其他 CNKI 入口。

## 八之二、已知限制：自动化访问可能长期不可用

2026-07-23 的四轮审计共发起六次真实检索（4 次无头 + 1 次有头 + 1 次诊断探针，
5 个不同检索词，跨四个会话），**全部在提交检索的瞬间被拦截**，落到
`kns.cnki.net/verify/home`、标题"安全验证"、正文可见文本 0 字符。

零请求的本地检查查明机制：Playwright 在**有头与无头模式下 `navigator.webdriver` 均为 `True`**。
知网拦截的是自动化控制本身，与渲染模式无关。因此"增加有头模式开关"不能解决问题。

诊断同时确认了三件事：首页契约验证通过；拦截发生在提交检索的瞬间；
状态机处理正确（如实报告 `challenge_detected`，未重试也未绕过）。

由此确定本能力的定位：

- CNKI 检索是**尽力而为的补充能力**，不是可依赖的主检索路径。
  `ai4scholar` 始终是主要来源（见第七节）。
- `challenge_detected` 必须携带可操作的替代路径提示，且明确它**不等于**"该主题无文献"。
- 文档需明确写出该能力可能因站点安全策略持续不可用，且这不是安装故障。

**明确不采用**的规避手段（违反第九节与 SKILL.md 的检索边界）：
指纹伪装、User-Agent 伪造、代理或出口轮换、抹除 `navigator.webdriver`、
复用用户已登录的浏览器配置文件。

经 `connect_over_cdp` 接入用户自行完成验证的浏览器属可选架构，
但与"不使用用户浏览器配置文件"的边界冲突，需先做产品决策，本版本不实现。

## 九、安全、许可与数据边界

- 对 `cnki-search-skill-main.zip` 只进行清洁重写，不复制无许可证源码；
- 不读取、复制、提交或打包三个压缩包中的浏览器运行状态和缓存；
- TLS 验证必须开启，不因代理环境关闭证书验证；
- CNKI 临时浏览器上下文不得导入系统代理、Cookie 或用户浏览器 profile；
- 日志不得包含动态令牌、Cookie、认证重定向参数或完整页面内容；
- 测试夹具只保存完成脱敏的公开检索与结果表最小结构；
- 安装包不得包含用户路径、浏览器状态、研究临时目录或压缩包原始源码。

## 十、测试先行要求

### 1. 目录匹配测试

- 十级优先顺序和五个来源区块校验；
- 中文全角半角、间隔号和“网络首发”等附加文字；
- 同一期刊的书写变体归并取最小层级，不得判为 `ambiguous`；
- 归并后仍有多个不同期刊候选时返回 `ambiguous`；
- 同一期刊多目录命中采用最高级并保留全部来源；
- 综合期刊目录在 Skill 与 MCPB 两种分发布局下都能定位；
- CSSCI 等来源的学科分类进入 `subject_categories`；
- 未匹配期刊不虚构级别；
- Windows 子进程固定 UTF-8，消除中文输出解码失败。

### 2. 公开页面测试

- 首页默认字段确认为主题；
- 只填写公开首页检索框，不进入高级或专业检索；
- 结果页正确解析篇名、期刊、日期和年度；
- 非期刊文献不进入正式备选清单；
- 题名、期刊或发表年度任一缺失时计入不完整记录，并返回 `partial`；
- 结果 URL、详情 URL 和下载 URL 不进入输出；
- 验证码、登录跳转、403、429和页面变化立即停止；
- 固定第一页且最多 20 条；
- 临时上下文关闭后不保留浏览器状态。

### 3. 集成与验收测试

- 在空 Cookie、无 WebVPN、无机构认证的全新临时上下文完成一次真实主题检索；
- 使用脱敏样本验证结果解析和目录判定；
- 对 `经济研究` 等代表期刊正确返回级别、全部来源和学科分类；
- 对未知期刊返回 `unmatched` 并保留记录；
- 与模拟 ai4scholar 结果完成去重和来源保留测试；
- MCP、Skill、插件和独立解压包只暴露公开检索能力；
- 安装后的 Codex、Claude Code 和 Claude Desktop 不再出现登录、状态、详情、导出和下载工具。

## 十一、迁移与清理

- `cnki_status`、`cnki_login`、`cnki_fetch_details`、`cnki_export`、`cnki_download`、`cnki_close_session`；
- WebVPN、直连高级检索、专业检索及入口解析代码；
- 会话持久化、详情、导出、下载和文件校验模块；
- 对应的 CLI 子命令、MCP 工具、文档、测试和安装配置；
- 所有旧入口常量、动态 WebVPN URL 和访问授权参数。

保留并改造：

- `cnki_search` 名称，但收窄为公开主题检索；
- 公开结果题录模型和结构化状态；
- 串行限流与立即停止原则；
- `Academic_Journal_Master_Directory_20260715.md`、目录校验和期刊查询器；
- 跨客户端共用实现及独立解压验证。

## 十二、完成标准

只有同时满足以下条件，才能认定公开主题检索实施完成：

1. 旧 WebVPN、高级检索、专业检索、详情、导出和下载能力不再暴露；
2. 全新无 Cookie 临时上下文能够从公开首页完成主题检索；
3. 每条正式结果均具有非空的篇名、期刊和可核验发表年度，任一字段缺失的记录只进入 `incomplete_records`；
4. 目录匹配返回最高优先级、全部来源目录和学科分类；
5. 未匹配或歧义记录不会被误判或删除；
6. 遇到访问限制或验证时停止，不采用绕过措施；
7. 单元、集成、打包和跨客户端测试全部通过；
8. 安装包不含会话数据、缓存、动态令牌、固定用户路径或无许可证源码。
