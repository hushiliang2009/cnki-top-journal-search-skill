# GitHub Actions Node.js 24 升级设计

## 目标

消除 GitHub Actions 对 Node.js 20 的弃用预警，将仓库使用的四个 GitHub 官方 Action 升级到当前稳定主版本，同时保持现有 CI 任务、输入参数、产物名称和执行顺序不变。

## 版本选择

采用官方文档推荐的主版本引用：

- `actions/checkout@v7`
- `actions/setup-python@v7`
- `actions/upload-artifact@v7`
- `actions/download-artifact@v8`

截至 2026 年 8 月 6 日，对应最新稳定发行版分别为 `v7.0.1`、`v7.0.0`、`v7.0.1` 和 `v8.0.1`。四个版本均使用 Node.js 24。官方说明要求 Actions Runner 不低于 `v2.327.1`；本仓库仅使用 GitHub 托管 runner，不引入自托管 runner 兼容性问题。

继续使用主版本标签，不固定补丁版本或提交 SHA。这与仓库现有维护方式一致，可自动获得同一主版本下的兼容性修复。

## 修改范围

仅修改以下内容：

1. `.github/workflows/ci.yml` 中四类官方 Action 的版本引用。
2. 通用版和环境版的工作流契约测试，使其验证新的主版本并拒绝旧版本。

不修改以下内容：

- 通用版和环境版的 Skill 版本号。
- 期刊目录、期刊成员、分组数量和检索优先级。
- 知网专业检索字段、WebVPN 页面操作和检索范围。
- CI 矩阵、Python 版本、安装器步骤、产物名称及 Release 规则。

## 实施与验证

先修改契约测试，使其要求新的 Action 主版本，并确认测试因现有工作流仍引用旧版本而失败。随后只替换工作流中的版本引用，再运行：

1. 通用版和环境版工作流契约测试。
2. 两版完整非联网测试，分别在独立 Python 进程中执行。
3. `ruff`、`mypy`、目录校验和 `git diff --check`。
4. GitHub PR 的完整跨平台 CI。

若新主版本导致行为差异或 CI 失败，优先依据官方迁移说明调整配置；若无法在不改变现有 CI 行为的前提下解决，则撤回本次独立变更，不影响已经发布的通用版 0.5.2 和环境版 0.3.2。
